# Separate GPU ComfyUI executor runbook

This runbook installs a complete pinned ComfyUI executor outside the
VideoOps monorepo. VideoOps owns projects, revisions, queue policy, monitoring,
artifacts, and review; ComfyUI and MiniMax H3 own inference only. Do not clone
ComfyUI, MiniMax H3, or model weights into this repository.

The exact source and model pins are in [`pin-manifest.json`](./pin-manifest.json).
The frontend pin is intentionally an exact commit, not the repository's moving
`HEAD`. Verify that the requested commit exists before deployment.

Section 0 fixes the deployment topology and section 8 covers a rented GPU
host. Read both before section 1 if the executor is not already running on a
private network you own.

## 0. Choose a topology first

Two facts in the VideoOps source decide the deployment shape before any
provisioning happens:

- the generation worker runs inside the API process
  (`apps/api/src/app.ts:4466`, `startGenerationWorker: true`), so there is no
  separate worker host to place;
- `LocalArtifactStore` is the only artifact backend
  (`packages/object-store/src/index.ts:73`), so every stored clip is written to
  the local filesystem of whichever host runs that process.

The host that runs the API therefore also holds PostgreSQL, the artifacts, and
the audit record, and the network path between that host and the executor
carries every generated byte. Choose the topology before section 1: it fixes
the `COMFY_*` values in section 4 and decides how much of the section 5 gateway
policy you actually need.

| Topology | API, worker, PostgreSQL, artifacts | ComfyUI and weights | Use when |
|---|---|---|---|
| **A — co-located** | GPU host | GPU host, bound to loopback | The first real H3 smoke run, and any short rental with no state worth keeping |
| **B — split control plane** | Separate always-on host | Rented GPU host, on demand | Ongoing use, where the GPU host is destroyed between sessions |
| **C — workstation control plane** | Developer laptop | Rented GPU host, on demand | Not recommended; see the caveat below |

### Topology A — co-located, for the Phase 8 smoke run

Run the whole VideoOps stack on the rented GPU host and bind ComfyUI to
loopback. The worker reaches the executor without crossing a network, so the
private-route invariant in section 4 holds by construction and no clip is
copied over a WAN link.

```dotenv
COMFY_MODE=remote
COMFY_BASE_URL=http://127.0.0.1:8188
COMFY_WS_URL=ws://127.0.0.1:8188/ws
COMFY_FRONTEND_URL=https://gpu-host.example.ts.net/comfy/
COMFY_AUTH_TOKEN=<secret-manager-reference>
ARTIFACT_ROOT=/srv/videoops/artifacts
```

In this topology the private worker vhost on port `8189` in section 5 is
unnecessary — the worker uses loopback. The browser-facing half of that section
is still required: the `/comfy/` route must deny `POST /prompt`, queue
mutation, and interrupt, and must set an exact `frame-ancestors` origin.

Because the GPU host is ephemeral, treat its PostgreSQL volume and
`ARTIFACT_ROOT` as evidence to collect before teardown, not as durable storage.
Export the run record and artifacts as part of the section 7 evidence step.

### Topology B — split control plane, for ongoing use

Run VideoOps on a small always-on host with no GPU, and rent the GPU host for
inference only. The control plane keeps the durable record across GPU
teardowns, and the GPU host holds nothing that cannot be rebuilt from
`pin-manifest.json` plus the model volume.

```dotenv
COMFY_MODE=remote
COMFY_BASE_URL=http://comfy-gpu.example.ts.net:8189
COMFY_WS_URL=ws://comfy-gpu.example.ts.net:8189/ws
COMFY_FRONTEND_URL=https://studio.example.com/comfy/
COMFY_AUTH_TOKEN=<secret-manager-reference>
COMFY_REQUEST_TIMEOUT_MS=15000
ARTIFACT_ROOT=/srv/videoops/artifacts
```

The two hosts must share a private network. Section 8 describes how to build
one that satisfies section 5's assumptions when the GPU host is rented rather
than owned.

### Topology C — laptop control plane

Workable, but it has three costs that topologies A and B do not:

- the in-process worker stops when the laptop sleeps. Queued attempts are safe;
  `claimNext` only claims `status = 'queued'` rows whose lease is null or
  expired (`packages/db/src/index.ts:2649`), so they are picked up when the
  worker returns. An attempt already `running` is not reclaimed — the worker
  exhausts its reconnect and history-reconciliation retries and transitions the
  attempt to `timed_out` with `GENERATION_TIMEOUT`
  (`apps/api/src/generation.ts:2104`). A sleep mid-generation costs that
  attempt;
- every artifact crosses a residential uplink before it is stored;
- the executor cannot run on the laptop at all, so this saves no rental time.

Apple Silicon cannot host the pinned executor. `COMFY_MODE=fake` remains the
correct local mode for development on a workstation, and is already the
default in `.env.example`. Development does not change when a GPU host exists.

## 1. Fetch the pinned executor outside this repository

Choose a persistent path on the GPU host, for example `/srv/comfyui-h3`, and
keep it outside the VideoOps checkout:

```sh
export COMFY_ROOT=/srv/comfyui-h3
git clone https://github.com/Comfy-Org/ComfyUI.git "$COMFY_ROOT"
git -C "$COMFY_ROOT" checkout 8a33128f2f8c5585c57486c07de481241e70a39c
git -C "$COMFY_ROOT" rev-parse HEAD
```

Install the Python and CUDA dependencies using the GPU vendor's supported
Python/CUDA combination. The pinned ComfyUI checkout is the source of truth
for its dependency file; do not install an unpinned `main` checkout over it:

```sh
python3 -m venv "$COMFY_ROOT/.venv"
"$COMFY_ROOT/.venv/bin/python" -m pip install --upgrade pip
"$COMFY_ROOT/.venv/bin/pip" install -r "$COMFY_ROOT/requirements.txt"
```

Use the appropriate vendor-supported PyTorch wheel when the requirements file
does not select it for the host CUDA version. Record the Python, CUDA, GPU,
PyTorch, and ComfyUI commit in the deployment evidence.

## 2. Install the VideoOps browser plugin

Copy only the frontend-only integration package from the checked-out VideoOps
source tree into ComfyUI's custom-node directory. This package has no Python
execution nodes and no runtime dependency:

```sh
export VIDEOOPS_ROOT=/path/to/deploy_Mh3
install -d "$COMFY_ROOT/custom_nodes/comfyui-videoops/web"
install -m 0644 "$VIDEOOPS_ROOT/integrations/comfyui-videoops/__init__.py" \
  "$COMFY_ROOT/custom_nodes/comfyui-videoops/__init__.py"
install -m 0644 "$VIDEOOPS_ROOT/integrations/comfyui-videoops/web/bridge-contract.js" \
  "$COMFY_ROOT/custom_nodes/comfyui-videoops/web/bridge-contract.js"
install -m 0644 "$VIDEOOPS_ROOT/integrations/comfyui-videoops/web/bridge-runtime.js" \
  "$COMFY_ROOT/custom_nodes/comfyui-videoops/web/bridge-runtime.js"
install -m 0644 "$VIDEOOPS_ROOT/integrations/comfyui-videoops/web/videoops.js" \
  "$COMFY_ROOT/custom_nodes/comfyui-videoops/web/videoops.js"
```

Restart ComfyUI after installing the plugin. The browser-facing route must load
the pinned frontend and the extension from this custom-node directory. ComfyUI
is the top-level graph shell; the plugin embeds a Studio-origin iframe with a
fresh nonce and exact `parentOrigin`. The VideoOps bearer token is held only by
that Studio iframe and must never enter the ComfyUI origin. Do not append a
bearer token, private executor URL, or model path to the iframe URL.

## 3. Place models and persist executor data

Obtain the model files through the publisher's approved distribution and
record publisher-provided checksums when available. Never invent checksums and
never commit weights:

```sh
mkdir -p \
  "$COMFY_ROOT/models/diffusion_models" \
  "$COMFY_ROOT/models/text_encoders" \
  "$COMFY_ROOT/models/vae" \
  "$COMFY_ROOT/models/loras" \
  "$COMFY_ROOT/input" \
  "$COMFY_ROOT/output"
```

Required H3 filenames:

```text
models/diffusion_models/minimax_h3_fl2va_pruned_int8_convrot.safetensors
models/text_encoders/qwen3vl_32b_minimax_h3_nvfp4_awq.safetensors
models/vae/minimax_h3_video_vae_fp16.safetensors
models/vae/minimax_h3_audio_vae_fp32.safetensors
models/loras/minimax_h3_fl2v_turbo_8step_v1.0_comfyui_bf16.safetensors  # optional retained turbo branch
```

Back up or volume-mount `models`, `input`, and `output` independently. The
VideoOps worker later downloads output through the private executor API and
stores a separate artifact; it does not treat a ComfyUI filesystem path as a
client resource ID.

## 4. Run ComfyUI on a private network

Bind the executor to a private interface or localhost behind a gateway. Allow
only the VideoOps worker (and the authenticated editor gateway where required)
to reach port `8188`. Configure the worker with private values such as:

```dotenv
COMFY_MODE=remote
COMFY_BASE_URL=http://comfy-private.internal:8189
COMFY_WS_URL=ws://comfy-private.internal:8189/ws
COMFY_FRONTEND_URL=https://studio.example.com/comfy/
COMFY_AUTH_TOKEN=<secret-manager-reference>
COMFY_REQUEST_TIMEOUT_MS=15000
```

The `COMFY_AUTH_TOKEN` value belongs only to the VideoOps worker and gateway.
Do not put it in an iframe URL, browser JavaScript, logs, traces, or the
public `/v1/executor` response. The browser receives only the safe
`COMFY_FRONTEND_URL` route from that response. The separate VideoOps bearer
token likewise remains in the Studio origin and is never copied into ComfyUI
storage, globals, DOM, or bridge messages.

Run the pinned executor using the host's approved CUDA launch options, for
example:

```sh
"$COMFY_ROOT/.venv/bin/python" "$COMFY_ROOT/main.py" \
  --listen 0.0.0.0 \
  --port 8188 \
  --disable-auto-launch
```

Do not expose this listener directly to the public Internet.

## 5. Split the private API route from the browser editor route

Use an authenticated reverse proxy or service mesh. The private worker route
may reach the full ComfyUI protocol, including `POST /prompt`; the browser
route must not. A minimal Nginx policy shape is:

```nginx
map $http_upgrade $connection_upgrade {
    default upgrade;
    '' close;
}

upstream comfy_gpu {
    server comfy-gpu.internal:8188;
}

# A separate private vhost is reachable only by the VideoOps worker. The
# gateway obtains this secret from its secret manager; it is never a browser
# header or URL value.
server {
    listen 8189;
    server_name comfy-private.internal;
    allow 10.20.0.0/16; # replace with the worker network
    deny all;
    location / {
        proxy_pass http://comfy_gpu;
        proxy_set_header Authorization $comfy_upstream_authorization;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;
    }
}

# Project Studio's SSO/VPN route serves the editor but no queue mutation.
location /comfy/ {
    auth_request /_studio_auth;
    proxy_pass http://comfy_gpu/;
    proxy_set_header Authorization $comfy_upstream_authorization;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection $connection_upgrade;
    proxy_set_header Host $host;
    add_header Content-Security-Policy "frame-ancestors https://studio.example.com" always;
    add_header X-Content-Type-Options nosniff always;
    limit_except GET HEAD OPTIONS { deny all; }
}

# Keep explicit denies beside the broad method policy so a future route change
# cannot accidentally make these mutation endpoints browser-accessible.
location = /comfy/prompt { return 405; }
location = /comfy/interrupt { return 405; }
location = /comfy/free { return 405; }
location = /comfy/queue {
    limit_except GET { deny all; }
    proxy_pass http://comfy_gpu/queue;
}
```

The exact gateway syntax varies by deployment. The invariant is that browser
requests can reach the authenticated editor/static/read surface and its
WebSocket upgrade, while browser `POST /prompt`, queue mutation, interrupt,
and other execution-control methods are denied by the gateway. The gateway
may add the upstream bearer header server-side; it must never forward that
secret to the browser. Set an exact `frame-ancestors` policy for the Project
Studio origin and do not use `*`.

Prefer a same-site `/comfy/` route. If a separate origin is unavoidable,
configure an exact origin allowlist for CORS and bridge messages, preserve the
authenticated WebSocket gateway, and keep the private worker route on the
internal network.

## 6. Verify readiness, plugin loading, and the live protocol

From the private worker network, verify the safe readiness surface and record
the results without recording tokens, raw model paths, prompts, or output
bytes:

```sh
curl --fail --silent --show-error \
  -H "Authorization: Bearer $COMFY_AUTH_TOKEN" \
  http://comfy-gpu.internal:8188/system_stats
curl --fail --silent --show-error \
  -H "Authorization: Bearer $COMFY_AUTH_TOKEN" \
  http://comfy-gpu.internal:8188/object_info
curl --fail --silent --show-error \
  -H "Authorization: Bearer $COMFY_AUTH_TOKEN" \
  http://comfy-gpu.internal:8188/queue
```

Check that `/object_info` contains the required H3 node classes and exact
loader choices from `pin-manifest.json`. In an authenticated browser session,
open the `/comfy/` route as the top-level shell with a fresh nonce and verify:

1. the pinned frontend loads without a direct private hostname;
2. the plugin creates a Studio-origin iframe and receives `panel.ready` from
   the exact child window before sending `comfy.context`;
3. **Managed Run** calls public `graphToPrompt()` and produces one
   `workflow.exported` message containing both editor and API graph data;
4. the Studio child alone calls VideoOps, while no VideoOps bearer token,
   private URL, raw filesystem path, or credential appears in the ComfyUI
   origin, console, or network URL;
5. browser `POST /comfy/prompt`, queue mutation, and interrupt requests return
   the gateway's denial response;
6. the Studio child sends `run.status` back to the plugin for the read-only
   topbar/bottom-panel feed. The pinned frontend has no supported queue
   interception API, so native controls are disabled and no queue internals are
   patched.

From the VideoOps checkout, run the opt-in live contract check only when this
private pinned executor is available:

```sh
COMFY_LIVE_TEST=1 COMFY_MODE=remote pnpm test:comfy-live
```

This verifies readiness, capability evidence, safe invalid-prompt handling,
queue normalization, and WebSocket parsing. It does not claim that H3 was
generated. Record a real clip, its exact pins, and its media evaluation
separately before making any real-generation claim.

## 7. Evidence and rollback

Record:

- the exact commits in `pin-manifest.json` and `git rev-parse` output;
- GPU/CUDA/Python/PyTorch versions;
- capability fingerprint and live contract result;
- gateway route/method policy and `frame-ancestors` origin;
- bridge readiness and dual-graph export result;
- publisher-supplied model checksums, if supplied;
- whether a real clip was generated and evaluated.

To roll back, stop the executor, restore the previous complete ComfyUI
checkout and compatible model volume, reinstall the matching bridge files,
and rerun the readiness plus bridge checks. Do not change a pin silently or
claim a live H3 generation from fake ComfyUI evidence.

## 8. Rented-GPU lifecycle

Sections 1-7 assume a GPU host on a private network you already control.
This section covers the case where the host is rented per hour and rebuilt
often. It changes no invariant; it supplies the private network, the durable
model volume, and the bring-up and teardown order that the earlier sections
take for granted.

### 8.1 Build the private network with a WireGuard mesh

Section 4 requires the executor to be unreachable from the public Internet, and
section 5 filters the private worker vhost by source CIDR. A rented host has no
such network, and its public address changes on each rental. Do not solve this
by exposing port `8188` and relying on `COMFY_AUTH_TOKEN` alone; that token is a
second line of defence, not a perimeter.

Join the control plane and the GPU host to a WireGuard mesh — Tailscale,
Netbird, or a self-hosted WireGuard hub are all adequate — and bind the
executor to the mesh interface only:

```sh
"$COMFY_ROOT/.venv/bin/python" "$COMFY_ROOT/main.py" \
  --listen 100.101.102.103 \
  --port 8188 \
  --disable-auto-launch
```

Replace the example with the host's own mesh address. Verify with
`ss -tlnp` that nothing is bound to `0.0.0.0`, and confirm from an off-mesh
host that the port does not answer.

The mesh CIDR then becomes the `allow` directive in the section 5 private
vhost. For a Tailscale mesh:

```nginx
allow 100.64.0.0/10;  # tailnet CGNAT range; narrow further if your ACLs allow
deny all;
```

Prefer the mesh provider's own ACLs over the CIDR filter where available:
grant the control-plane node a tag that permits `tcp:8189` on the GPU node, and
grant nothing else. The CIDR filter stays as defence in depth.

**Use a stable mesh hostname, never the provider's public IP.** The VideoOps
bridge validates an exact `parentOrigin`, and the section 5 gateway sets an
exact `frame-ancestors` origin. Both break when the address changes on
re-rental. Mesh DNS — Tailscale MagicDNS or an equivalent — gives the host a
name that survives rebuilds, so `COMFY_BASE_URL`, `COMFY_WS_URL`, and the
gateway policy stay correct without editing configuration each session.

### 8.2 Keep the models on a volume that outlives the host

The five files in `pin-manifest.json` are tens of gigabytes. Re-downloading them
on every rental usually costs more GPU-hours than the generation work itself.

Attach a persistent block volume, keep it out of the ephemeral boot disk, and
mount it before starting the executor:

```sh
mkdir -p /mnt/h3-models
mount /dev/disk/by-id/<persistent-volume> /mnt/h3-models
ln -sfn /mnt/h3-models "$COMFY_ROOT/models"
```

Put on the persistent volume:

- `models/` — the diffusion model, text encoder, both VAEs, and the optional
  turbo LoRA;
- the publisher-supplied checksums recorded in section 3, so a rebuilt host can
  be verified against them rather than trusted.

Do not put `output/` on it. The worker downloads each attempt's output through
the private executor API and stores its own authorized artifact under
`ARTIFACT_ROOT` on the control plane; the executor's `output/` directory is
scratch space, not a client resource.

If the provider offers snapshots, snapshot the volume once after the first
verified model load. Rebuilding from a snapshot is faster than any download and
preserves the exact files the capability fingerprint was recorded against.

### 8.3 Bring-up order for a fresh rental

Run in this order. Do not point the control plane at the new host until step 5
passes.

1. Provision the host, join it to the mesh, and confirm its mesh hostname
   resolves from the control plane.
2. Mount the persistent model volume (8.2).
3. Install the pinned executor (section 1) and the frontend bridge (section 2).
   Record `git rev-parse HEAD` for both pinned refs.
4. Start the executor bound to the mesh interface (8.1) and start the gateway
   with the section 5 route and method policy.
5. Run the section 6 readiness checks from the control-plane host — not from
   the GPU host, so the check exercises the real network path. `/object_info`
   must contain every class in `requiredApiNodeClasses` from
   `workflows/minimax-h3/compatibility-manifest.json`.
6. Set the `COMFY_*` values for the chosen topology and start the VideoOps API.
   `GET /v1/executor` must report ready before submitting a run.
7. Run the opt-in live contract check once per rebuilt host:

   ```sh
   COMFY_LIVE_TEST=1 COMFY_MODE=remote pnpm test:comfy-live
   ```

A rebuilt host is a new executor. Its capability fingerprint is pinned onto
each new revision at submit time, so revisions created against the previous
host remain accurate; they are not retroactively revalidated.

### 8.4 Teardown without losing the record

Destroying the GPU host does not corrupt VideoOps state, but it is not free
either. Before teardown:

1. Stop submitting new runs and let the queue drain. Queued attempts are safe
   across any outage — they are reclaimed by lease expiry
   (`packages/db/src/index.ts:2649`) — but an attempt already `running` when
   the executor disappears cannot be reclaimed. The worker exhausts its
   reconnect and history-reconciliation retries and transitions it to
   `timed_out` with `GENERATION_TIMEOUT` (`apps/api/src/generation.ts:2104`).
   Retry then creates a derived attempt, so the lineage stays intact and the
   work is repeated rather than lost.
2. Confirm every artifact for the session is stored under `ARTIFACT_ROOT` on the
   control plane. In topology A this is on the host you are about to destroy —
   copy it off, along with a PostgreSQL dump, as part of the section 7 evidence
   step.
3. Detach rather than delete the model volume (8.2).

### 8.5 Arm the cost breaker before the first rental

Cost is recorded on every attempt regardless of configuration, but enforcement
is off by default on the managed run path. `POST /v1/runs` without a
`projectId` auto-creates its project with `budgetMicrousd: null`
(`apps/api/src/app.ts:2555`), and null means no enforcement
(`apps/api/src/generation.ts:670`). `PROJECT_DEFAULT_BUDGET_USD` applies to the
explicit `POST /v1/projects` path, not to auto-created run projects.

With a metered GPU this is worth arming. `POST /v1/runs` accepts an optional
`projectId` (`apps/api/src/app.ts:274`) and reuses that project's budget, and
the Studio client already accepts the field (`apps/web/src/api.ts:537`).
Create one long-lived project with an explicit `budgetUsd` and submit runs
against it.

The ComfyUI managed panel does not currently pass `projectId`, so every run
started from the graph shell gets its own budget-less project. Until it does,
a budget is enforceable only for runs submitted with an explicit project.

### 8.6 Verify the hardware before renting

The pinned profile is not portable across GPU generations, and an
incompatible rental is the most expensive failure available here. Before
committing to an instance type, confirm against MiniMax's own deployment
notes for `MiniMax-AI/MiniMax-H3` at the ref in `pin-manifest.json`:

- **Quantization support.** The pinned text encoder is
  `qwen3vl_32b_minimax_h3_nvfp4_awq.safetensors`. NVFP4 is an NVIDIA Blackwell
  data type; confirm whether the publisher supports it on the generation you
  intend to rent, and what the fallback path costs if it is emulated. The
  pinned diffusion model is a separate `int8` quantization with its own
  requirements.
- **Total VRAM.** Size it from the actual bytes of the five files in
  `pin-manifest.json` plus activation headroom at the profile defaults in
  `compatibility-manifest.json` (960x544, 24 fps, 20 steps, non-turbo).
  Do not estimate from parameter counts.
- **Persistent volumes and stop/start.** The provider must support detaching a
  volume and reattaching it to a later instance, or 8.2 does not apply.

Avoid per-second serverless GPU products for this executor. The VideoOps
Comfy client observes a live WebSocket and reconciles against `/history`
(`packages/comfy-client/src/index.ts`); it requires a persistent ComfyUI
process, not a cold-started function.

Record the resolved GPU model, driver, CUDA, Python, and PyTorch versions in
the section 7 evidence set. A generation claim is valid only against the
hardware and pins it was produced on.
